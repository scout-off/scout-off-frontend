# Add wallet-keyed server store for recently viewed players

## Issue Numbers
- #1154: Server-side persistence for recently viewed players
- #1155: Acceptance criteria for recently viewed feature

## Changes

### New Files

1. **`lib/migrations/recentlyViewedMigrations.ts`** - Migration for initial schema
   - Creates `recently_viewed` table with scout_wallet, player_id, viewed_at columns
   - Adds indexes and unique constraint

2. **`lib/recentlyViewedStore.ts`** - SQLite-backed server store
   - Singleton pattern like `watchlistStore`
   - Methods: `record`, `remove`, `clearForWallet`, `list`
   - Caps entries at 50 per scout

3. **`lib/recentlyViewedClient.ts`** - API client wrapper
   - `fetchRecentlyViewed()` - GET /api/recently-viewed
   - `recordView(playerId, viewedAt)` - POST /api/recently-viewed
   - `removeView(id)` - DELETE /api/recently-viewed

4. **`app/api/recently-viewed/route.ts`** - API endpoint
   - GET: List authenticated scout's recently viewed players
   - POST: Record a player view
   - DELETE: Remove an entry

### Modified Files

1. **`hooks/useRecentlyViewed.ts`** - Hybrid localStorage + server store
   - For authenticated scouts: Uses server store via `/api/recently-viewed`
   - For anonymous sessions: Falls back to localStorage (unchanged behavior)
   - If server recording fails: Automatically falls back to localStorage
   - Syncs server entries to localStorage when switching to anonymous mode

2. **`types/index.ts`** - Add `RecentlyViewedEntry` type
   - `id: number` - Database ID
   - `playerId: string` - Player identifier
   - `name: string` - Player name
   - `position: string` - Player position
   - `viewedAt: number` - Unix ms timestamp

## Acceptance Criteria

- A connected scout's recently viewed players are persisted server-side, keyed by wallet address
- The list is available (and consistent) across two different browsers/devices for the same connected wallet
- An unconnected/anonymous browsing session keeps working via the existing localStorage-only behavior, with no regression

## Notes

- Server store caps entries at 50 per scout to avoid unbounded storage growth
- Follows same pattern as `watchlistStore`/`savedSearchStore`
- localStorage fallback ensures graceful degradation for unauthenticated sessions
